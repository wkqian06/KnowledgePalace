# Assess an experiment or analysis plan

`feasibility <idea|file|project>` judges whether a specified design can answer the
question and can be executed under known conditions. `idea refine` develops the
idea and contribution; `research` stores the continuing decisions. Call them only
when that additional task is needed.

Read the proposal, available project materials and relevant literature. Establish
what is supplied, what is proposed and what is unknown. Newly adopted literature
uses [ingest](ingest.md); a publication's resources are not the user's resources.

Reason about the decisive issues for this design:
- What explanations or effects does the question distinguish?
- Do variables, observations, sampling scale and independent units match that target?
- Can controls, comparisons or interventions distinguish the alternatives, and how
  would uncertainty or validation change the interpretation?
- Are required data, access, computation, storage, skills and time actually available?

Use only relevant domain considerations. For environmental/event studies this can
include event selection, time of information availability, spatial/temporal support,
product uncertainty, independent evaluation and physical interpretation. Do not turn
these examples into compulsory fields for every discipline.

Return one of: feasible / feasible once stated conditions are met / design needs
revision / cannot be judged yet (stated in the user's language), with the evidence
and decisive conditions. Separate scientific identifiability
from operational feasibility. Name the smallest useful pilot, its comparison,
possible outcomes and what would change the decision. Estimate resources only from
supplied information or an actual authorized measurement; otherwise state the missing
input. No numeric feasibility score or automatic statistical-test selection.

On a save request, keep the judgment, design and next action in project research
notes. Actual later results enter registered user materials and Observations, with
their relation to the judgment. Do not execute the proposed experiment without a
request to do so.
